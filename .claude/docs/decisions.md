| D17 | 2026-09-06 | Feature design and categorical dev reference. 5 features: 3 continuous (feature_1/10 bins, feature_2/8 bins, feature_3/5 bins) and 2 categorical (feature_4/4 levels A-D at 0.45/0.30/0.15/0.10, feature_5/3 levels X-Z at 0.60/0.30/0.10). Features table at D9 grain (one row per user_ref_num). Generalized solver: `psi_from_alpha`, `solve_alpha`, `tilt_weights` accept optional `dev_weights` for non-uniform dev (categorical features). For uniform q (continuous), the formula recovers the original: sum(q_i*t_i) = 0 → normalization is 1 → w_i = (1+alpha*t_i)/n. For non-uniform q, the normalization sum(q_i*(1+alpha*t_i)) != 1 in general; the code normalizes correctly. Categorical tilt direction: `tilt_dir = -1` reverses which end of the level list is boosted. For feature_4, level D (10% dev, minority) gains mass; for feature_5, level Z (10% dev, minority) gains mass. This models channel-mix drift away from the dominant source — a recognizable real-world pattern that pairs with the deteriorating score distribution (PSI story). The alternative (tilt_dir = +1, boosting the already-dominant level) would have the drift direction be an artifact of list order with no real-world analog. Per-segment PSI is RNG-invariant: bin counts come from deterministic_allocate (no randomness), and integer scores with +1L boundary alignment always map back to their originating bin under cut(right=TRUE, include.lowest=TRUE). Verified empirically: seed=42 vs seed=43 produce bit-identical per-segment PSI; the KS task's regeneration (D20) confirmed all five per-segment values bit-identical to pre-change values. Shifting the RNG stream (e.g., by adding the approval-rate sample() call in D20) causes some scores to cross All Segments bin boundaries. Observed: All Segments PSI moved from 0.08472267 to 0.08351459 (delta -0.00121) when the KS task's regeneration changed the stream.
